# Release signing and distribution

## Current state and transition boundary

At the preparation baseline, the private repository has an active, manually dispatched `Publish Android` workflow. Its previous implementation signs during `verify`, has no owner-review environments and does not require protected `main`; it refuses public publication. The owner has moved the existing `android-debug-1.0` prerelease to draft with its debug APK and checksum retained. That is not a production release, and the draft assets are not redistributed by this replacement. Repository visibility changes also expose existing source history and tags; hiding a workflow is not an exposure review.

The replacement described below is prepared source, **not proof that remote protection, environments, credentials or publication are configured**. Do not enable it or dispatch a release until the setup is verified. No signing credential is bundled. `verify` defaults to unsigned verification only; it neither signs nor publishes. `release` builds, waits for signing approval, then waits independently for publishing approval. It does not reuse artifacts from an old verification run.

The earlier private GitHub Free design relied on manual dispatch because enforced required-reviewer environment gates are unavailable on that plan. Manual dispatch is **not** equivalent to an approval gate. The public-transition design replaces that proposal; if the required protection is unavailable, keep publication disabled rather than remove its checks. Authorized workflow/configuration editors can exfiltrate available secrets, and owner/account compromise remains a trust boundary.

## Owner-controlled setup and safe ordering

1. Disable the old publisher before changing visibility. Keep the existing debug release in draft, review reachable source/history and contributor access, and preserve the original-code [MIT license](../LICENSE). Dependencies are not relicensed: [third-party notices and full licenses](licenses/third-party.txt) are included in each new APK and accessible offline in **Setup → Licenses**, including the version-specific SQLCipher Community grants and bundled OpenSSL 3.0.16 attribution. Recheck resolved/native dependencies and notice obligations when updating them; this preparation is not legal certification. Do not publish credentials, real recipient data, toolchains, imported schedules or private runtime databases.
2. Review and install the replacement workflow through the owner's chosen source-change process. Keep publishing disabled through the public cutover/protection setup; do not run the legacy workflow on any ref. Restrict workflow editing and protect `main` from force pushes and deletion. For a sole-owner repository, do not require an impossible second-person PR approval or a nonexistent CI status. A separate no-bypass force-push/deletion rule can protect everyone, while an owner-only update rule permits ordinary owner fast-forwards. Required status checks should be added only after their exact check contexts have run successfully; the manual publishing workflow is not an automatic per-commit CI check.
3. Configure **two separate environments**, `android-sign` and `android-publish`. Each has `mikeliddle` as its sole required User reviewer, self-review allowed, `can_admins_bypass=false`, and exactly one selected deployment branch policy: `main` (branch, not tag). Separate environments require two distinct owner approval decisions; approving signing is not approving publication. Agents must never approve either on the owner's behalf. Verify these settings after public transition; they do not turn on automatically. Unsupported or missing protection must leave publication disabled. Repository admins can still edit environment/workflow settings, so account security and trusted configuration editors remain a boundary.
4. With a separate secure credential handoff, provision a **dedicated Auto ExecSec production key**, not the debug key or another app's key. Keep the durable key and independently recoverable encrypted password/key backups outside GitHub and verify recovery. Cloud signing requires explicit authorization to place copies in GitHub. Enter `ANDROID_RELEASE_KEYSTORE_B64`, `ANDROID_RELEASE_KEY_ALIAS`, `ANDROID_RELEASE_STORE_PASSWORD` and `ANDROID_RELEASE_KEY_PASSWORD` as **`android-sign` environment secrets**, not repository secrets or `android-publish` secrets. Base64 is encoding, not encryption. Set the same reviewed public certificate fingerprint as `ANDROID_RELEASE_CERT_SHA256` in both environments: lowercase 64-character SHA-256 without colons. Use approved secret input, never chat, source, logs or password arguments. Without this handoff, signing must remain blocked.
5. Review Actions access, enabled refs/workflows and costs before enabling the replacement. Public Actions eligibility does not mean unlimited minutes/storage or permission for paid overages; choose runner/retention/concurrency controls and disable unapproved paid usage. Artifacts expire after one day. The workflow pins actions to full SHAs and independently authenticates Google's Windows Build Tools 36 archive with SHA-256 `aa1095cb14d83e483818a748a2c06faaeb8e601561b06a356a119a1b2ca280d3`. Re-review pins/checksums for any tool update; never substitute "latest".

## Verify, then deliberately request release

Set a coherent `versionCode`/`versionName` in `app/build.gradle.kts`, get the reviewed source onto protected `main`, and supply its exact full SHA and version to **Actions → Publish Android → Run workflow** on `main`.

Use default **verify** first: secret-free tests, release lint and an unsigned non-debuggable production APK. Inspect the successful test/lint results, exact commit/run/attempt, immutable unsigned artifact ID/archive digest, APK SHA-256 and package/version/permissions before requesting production work. Nothing is signed or published. A build alone is not phone/carrier verification.

Production APKs package **ARM64 (`arm64-v8a`) only**, including SQLCipher. Unsigned artifact inspection rejects other native ABIs or missing ARM64 SQLCipher. Debug retains its existing ABIs. This packaging choice requires a 64-bit Android OS, not merely an ARM64-capable processor; the minimum Android API remains 26. It does not establish SMS permission eligibility or carrier reliability.

Only `mikeliddle` can request or rerun **release**. The workflow repeats the secret-free build; the owner must check its new immutable artifact/hash and approve `android-sign`. A fresh runner has no source checkout, Gradle/project scripts or restored caches. It authenticates the exact artifact/run/attempt/hash and signing tools before exposing environment secrets to the signing step, uses restricted temporary key files and password environment injection, aligns before signing, verifies the dedicated certificate, and removes credentials on exit/failure.

The owner must then inspect the signed APK/hash/artifact and approve **`android-publish` separately**. Publishing receives no signing secrets and is the only job with ephemeral `GITHUB_TOKEN` `contents: write`; build/sign tokens are read-only. It revalidates exact artifact/run/attempt/archive/APK hashes, one expected signing certificate, alignment, package `fyi.mllab.autoexecsec`, reviewed versions, non-debuggable state, and the explicit permission allowlist: SMS send, phone state, notifications, exact alarms, boot and the app-private signature-protected dynamic receiver permission. This app legitimately has permissions; a no-permission check from another app is inappropriate.

Production `versionCode` must exceed existing `android-<code>` tags and release/draft versions. Existing tags/releases are never overwritten. Any change to reviewed `main`, missing guard/configuration, unknown artifact, unexpected permission/certificate/version or partial publication fails closed. Published release tags should separately block updates and deletion without bypass. On partial failure, inspect the draft/tag/assets rather than rerunning or forcing an overwrite.

After both approvals, only the verified `AutoExecSec.apk` and `SHA256SUMS` become release assets under `android-<versionCode>` on the verified **public** repository. Notes identify commit/version, run/attempt, immutable artifact, APK hash and public certificate fingerprint. Raw logs, metadata folders, test tools, data and signing material are not release assets. Verify the final source tag and asset digests. A signature proves integrity/key identity, not benign behavior, installer SMS eligibility or delivery reliability.

The production package is `fyi.mllab.autoexecsec`; debug builds use `fyi.mllab.autoexecsec.debug`. The Kotlin namespace and component classes remain `local.reminders`. The new application IDs are distinct installations, not updates or data migrations from `local.reminders` / `local.reminders.debug`; old app data, permissions and queues remain separate. A production signature cannot replace an installed package signed with another key. No uninstall, data migration or device install is authorized by running this publishing workflow.
